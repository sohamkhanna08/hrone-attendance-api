Also note anything you looked at and decided was **not** a defect, and why.

### Looked at and decided were not defects

- **`doc.pop("_id", None)` after `insert_one` in `create_employee`.** `insert_one` adds `_id` to the dict it was given, so removing it before returning is correct and keeps `_id` out of the response.
- **Storing `date` as a `"YYYY-MM-DD"` string and filtering it with `$gte`/`$lte`.** Zero-padded ISO dates sort in the same order as the dates themselves, so string range queries are correct (and intended by DATA_MODEL.md).
- **`load_dotenv()` at import time.** By default it does not override variables that already exist, so real environment variables still win over `.env`, as the contract requires.
- **Exact, case-sensitive `department` filter.** DATA_MODEL.md says `department` is case-sensitive, so `"sales"` must not match `"Sales"`.
- **Default shift `09:30`-`18:30` in `EmployeeIn`.** Matches the defaults in `openapi.yaml`.
- **`IST = timezone(timedelta(hours=5, minutes=30))` as a fixed offset.** India has no daylight saving time, so a fixed UTC+05:30 offset is correct.
